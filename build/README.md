# Build adapters

## Optional speech runtime

`speech-runtime.mjs` builds isolated Parakeet inference/features workers and
publishes matching ONNX Runtime MJS/Wasm, capture worklet and complete notices
under `speech/`. Models and TEN-VAD's engine are explicit upstream downloads;
they never enter the core HTML or static model payloads. Files above 20 MiB use
the existing verified-part transport to meet Pages' 25 MiB limit. The build
asserts exact runtime versions and the local serial initialization patch.
The [speech guide](../src/lib/assistant/speech/README.md) owns runtime/data
boundaries, reference provenance, licensing and verification commands.

## First-paint loading screen

`startup-preview.mjs` renders the owned Svelte loading gallery into the initial
HTML, including its scoped animation styles. The header and all nine drawings
therefore arrive together and animate before application JavaScript runs. The
browser hydrates that markup to attach real progress without replacing drawings
or restarting their animations. Responsive layout and reduced-motion behavior
come from the same components used during normal startup.

The Vite HTML adapter compiles the four loader components with Svelte's server
target, bundles its temporary renderer with pinned Rolldown, and inserts
the result at `<!-- startup-preview -->`. This happens during the build or a
development HTML request; it adds no application backend or runtime assets.
Development caches the result by component and progress-definition contents, so
new requests reflect edits without maintaining generated source files. Compiler
filenames and development CSS scoping match the browser compiler for hydration.

## Favicon generation

`favicons.mjs` derives nine checked-in files under `src/public` from the original
`src/assets/favicon.svg`, using pinned Sharp 0.35.5. The
[asset guide](../src/assets/README.md#favicon-outputs) owns the output inventory,
dimensions, artwork provenance and HTML fallback choices.

Run `npm run icons:generate` after source changes. `npm run icons:check` renders
all derivatives and compares exact bytes without writing; missing or stale
files fail with the regeneration command. `npm run build` runs this check
before Vite. The generator rejects symlink or nonregular destinations before
writing and changes only stale generated files. It does not require a browser
or external font service. Review regenerated bytes and browser appearance when
upgrading Sharp or changing the artwork.

## License preservation

`license-notices.mjs` preserves notices in the standalone production page.
Vite's built-in `build.license` inventory supplies the packages present in the
main JavaScript bundle. A worker plugin collects licenses from the actual module
graph of each inline worker before encoding it, including Git and filesystem
dependencies omitted by Vite’s main inventory. The adapter also reads the first-party license and additional
terms, local font notices (including Devicon's MIT license and brand notice),
vendored shadcn-svelte notice, and the two direct CSS
packages that have no JavaScript module inventory.

Full texts appear in an inert `<template id="license-notices">` in
`dist/index.html`. View the page source to read them. They do not render in the
editor, execute markup, or require network access. A missing or empty
notice fails the build.

`formatter-packages.mjs` builds 38 optional formatter packages from the exact
installed npm dependencies and the releases pinned in `formatter-artifacts.json`.
`formatter-artifacts.mjs` fetches a missing upstream artifact at build/development
startup, bounds its size, verifies SHA-256 and caches it under
`tmp/formatter-artifacts/`. Cached builds and browser tests require no network;
clean builds need access to those pinned release URLs, as they do to npm packages.
Artifacts are never downloaded from upstream by the running application. The main/worker virtual catalog contains only names,
versions, sizes, URLs and SHA-256 digests. Development serves these same static
bytes through Vite middleware; production emits them under `dist/formatters/`.
No formatter payload enters the main HTML. There are no runtime registry calls
or generated remote bundles. Release artifacts must preserve the package files
with their matching HTML; publishing a newer catalog is how updates are offered.

`package-artifacts.mjs` emits optional formatter/language envelopes above 20 MiB
as ordered static parts. Their trusted catalog includes each part's URL, byte
size and SHA-256; installation reconstructs and validates the original envelope.
The 38 formatter and twelve language packages are logical counts, not a fixed
count of hosted files. Every emitted file fits Pages' 25 MiB limit. Publish all
parts with their matching HTML, including the per-part metadata; do not omit a
large provider or move it to a different origin without updating the contract.

For an authorized manual working-tree publication, build with
`VITE_SOURCE_ARCHIVE_URL=./source.tar.gz` and include the reviewed corresponding
source archive at that path in the published directory. The Licenses and notices
view links to it. Include tracked source and reviewed new source files, the
lockfile and complete project/asset notices; exclude ignored local data,
credentials, caches, dependencies, and build output. The published source must
match the deployed application changes. Clean committed builds default to the
project's GitHub source link. `source.tar.gz` is optional hosting output and
participates in the complete deployment hash when present.

Wasm packages preserve the original plugin bytes and full notices obtained from
`getLicenseText()`. Prettier providers are independent minified browser ESM
bundles with embedded dependencies and no external imports; their actual module
graph supplies the full license inventory. Each JSON package contains identity,
version, payload kind, base64 payload and notices. The checksum covers the entire
package, including notices. A bounded locate-character fallback covers the Svelte
compiler's package, which omits its license file. Roslyn's wrapper-only Wasm
notice is supplemented with pinned Microsoft/compiler/runtime and Humanizer
notices under `licenses/`; the supplement is guarded by the exact binary digest. Packaging tests verify all 38
checksums, payload sizes, separation from the page and full Wasm notices.

Worker code splitting remains disabled so application workers stay inline.
Packaging checks ignore example HTML inside script strings and place main-page
notices at the actual final body close.

Some pinned dependencies omit standalone license files. The explicit fallbacks
under `licenses/` retain clean-git-ref's declared Apache license and attribution,
and diff3's complete source-header MIT notices. Their provenance is documented
in `licenses/README.md`; version or license changes require review, and diff3's
reviewed source hashes must also match. Keep these exceptions bounded when
upgrading dependencies rather than accepting unknown missing notices.

Singlefile keeps intermediate chunks until Vite has collected their licenses.
The adapter then embeds escaped notices and removes those chunks and Vite's
intermediate JSON. The core distribution contains 11 files:
`index.html`, `_headers`, and the nine generated public favicon files. Application
JavaScript, CSS, fonts and workers remain embedded in the HTML; favicon
compatibility files are intentionally external. Thirty-eight additional package files
live under `formatters/`, twelve language-engine packages under `languages/`, and
four type-library data packages under `types/`. All require explicit installation.
The HTML alone runs the
editor; formatting and semantic intelligence additionally require installed packages.
Keep this ordering when
updating Vite or the singlefile plugin. Cleanup requires one entry JavaScript
chunk without external or dynamic imports and at most one CSS bundle; an
unsupported shape fails before removing assets. Add explicit notices here when adding
direct CSS imports, fonts, or other vendored source. Acceptance scenarios verify
full-text preservation, failed inventories, and markup escaping; the browser
profile verifies the resulting template remains inert and readable.

## Optional upstream SDKs

`remote-packages.mjs` packages the pinned Octokit, GitBeaker and Bitbucket.js
adapters as three self-contained browser ESM artifacts under `remotes/`. Their
embedded catalog supplies exact sizes, versions and SHA-256 digests. Payloads and
complete dependency notices stay outside the core HTML and install only through
Settings or verified offline import. The owned remote loader shares the narrowly
permitted verified Blob import shape with the syntax loader. The
[upstream guide](../src/lib/remotes/README.md) owns authentication and transport.

## Optional language engines

`language-packages.mjs` compiles twelve separate self-contained module workers from
pinned npm dependencies. The generated trusted catalog stays in the main page;
payloads are served under `languages/` as `.language.json` packages with size,
SHA-256 and full application/dependency notices. Development and production use
the same packages. TypeScript library declarations are inside its optional
package. `type-packages.mjs` separates Browser/DOM, Web Workers, Node/Undici and
ScriptHost into four `.types.json` data packages under `types/`, each with exact
size, digest and complete notices. Only standard JavaScript declarations stay in
the engine. The trusted type catalog carries metadata without declaration payloads;
enabled packages enter the worker once at initialization. Browser path/protocol entrypoints replace Node interfaces; package
workers cannot have external module imports. See the
[language-engine guide](../src/lib/intelligence/README.md).

Community npm declarations are explicit runtime resource installs rather than
additional prebuilt artifacts. The owned installer worker and its pinned semver
resolver stay inline, with full dependency notices. It verifies npm archives and
retains declaration data only in a separate IndexedDB store. No package runtime
code or lifecycle script executes; analysis never contacts npm. The existing four
static type packages and their trusted catalog remain available offline.

`fourmolu-package.mjs` adds the official Fourmolu website Wasm build to the
formatter catalog. `formatter-artifacts.json` pins the immutable deployment URL,
55,005,943-byte payload and SHA-256; cached build inputs stay under ignored
`tmp/formatter-artifacts`. Its module package includes a separate `wasm` resource,
so the large binary is base64 encoded once. Both module and binary are covered by
the package checksum. The supplement under `licenses/` must match the binary
before packaging; module-graph notices cover the browser WASI and HTML adapters.

Dockerfile intelligence uses pinned `dockerfile-language-service` in an optional
local worker for completion, diagnostics and hover. Docker Hub tag requests are
disabled through an owned offline registry adapter; instruction, stage and variable
completion remain local. The build guards the replaced upstream implementation
by version and digest. Navigation and rename are not wired into the editor yet.

The Dockerfile AST UTF-8 helper uses native `TextEncoder` in browser packages.
The build guards that narrowly scoped adaptation with the upstream source digest.

`language-resources.mjs` packages PostgreSQL and WGSL binary resources in
verified optional envelopes and owns digest-guarded browser loading adaptations.
Taplo's published module already embeds its Wasm. Language workers receive local
resources before requests. Formatter modules receive resources through their
initialization export; no runtime resolver or CDN is involved.

`liquid-docs.mjs` loads checksum/size-pinned Shopify documentation and schema data
from `liquid-docs.json`, caching verified bytes under ignored `tmp/liquid-docs/`.
A cold build requires access to the pinned upstream files; the installed engine
requires no network. The package includes documentation, translations, schemas
and their MIT notice. No upstream latest lookup runs during build or use.

`syntax-packages.mjs` builds optional HCL/Terraform and Gentrace Handlebars beta parsers under `syntax/` as
`.syntax.json`, with pinned version, byte length, SHA-256 and complete notices.
Its factory receives shared CodeMirror/Lezer host modules rather than bundling
incompatible duplicates. `syntaxCatalog()` also supplies catalog metadata to the
repository worker. No optional parser payload is embedded in the core page. Included
GraphQL, WGSL and stable Handlebars syntax use the normal inline language-loading flow.

Conversation Markdown embeds KaTeX styles/fonts and a lazily initialized local
MathJax SVG renderer. MathJax's runtime import factory and unused CHTML output are replaced with
a static SVG bridge and package registration so standalone output retains no unresolved module imports.
The two MathJax font packages omit LICENSE files in 4.1.3; the pinned Apache
supplement under `licenses/` is guarded by package-metadata digests. Browser
include/snippet adapters retain mdit's MIT attribution in the embedded source
notice inventory. See the [Markdown guide](../docs/markdown.md).

Pi 1.3.0 packages omit license files from their published payloads. The guarded
MIT fallback `licenses/pi-1.3.0.txt` is the upstream `v1.3.0` license from
<https://github.com/earendil-works/pi/blob/v1.3.0/LICENSE>; package metadata
hashes in `license-notices.mjs` require review when those packages change.

## Optional browser inference

`browser-models.mjs` verifies the selected source-built Wllama runtime, license and
receipt. Its four static files are served under `browser-models/wllama/`; they
stay outside the core HTML and install only on explicit user action. The WebML
runtime is not redistributed; pinned upstream bytes are fetched and verified by
the browser installer. Model weights never enter the build. See the [source build
guide](browser-models/README.md) and [installation contract](../src/lib/assistant/browser/README.md).


`model-runtimes.mjs` builds optional LiteRT-LM 0.18.0, Transformers.js 4.3.1
(its own ORT 1.31.0 development pin), the separate original CPU/custom-device GPU
Strands adapters, and native decision prompt/readout helpers. Assets live under
`browser-models/runtimes/`; SDK files over 16 MiB are split on database-block
boundaries. The D3 exact-preflight, Elephant and Perplexity native builds retain
separate source-build receipts under `browser-models/wllama-*`.
`npm run models:generate` refreshes `runtime-artifacts.json` after an owned adapter
change; production builds verify those generated hashes before emitting bytes.
Development invalidates generated SDK bytes when their adapter sources change;
regenerate the pins before testing the updated runtime. The reviewed ORT engines
use matching Asyncify JS/Wasm pairs, including Transformers' 1.31 development
version whose legacy JSEP factory does not expose WebGPU initialization.
The guarded LiteRT patch changes only JS/Wasm asset resolution to verified Blob
URLs in a classic worker. Model files, backend, sampler and native templates stay
pinned. Model/tokenizer/config/head/license files are user-installed independently;
no model weights enter the build. Package license fallbacks are documented under
[`licenses/`](licenses/README.md).

# Architectural decision records

> [!IMPORTANT]
> Preserve the reasoning behind consequential project decisions in maintained ADRs.

## Purpose and format

Each record describes a coherent decision, context, constraints, and consequences.
An Important callout states the choice; focused sections explain the reasoning.
The records support future contributors without depending on chat history.

## Ownership

ADRs live in `docs/adr`, indexed alphabetically in `CONTRIBUTING.md`. Procedures
belong in operational guides and directory READMEs. Guides link to decisions;
ADRs avoid internal navigation links and may cite external supporting sources.

## Maintenance

Review affected decisions with implementation changes. State explicitly when a
choice is adopted for later implementation or remains unresolved. Replace stale
current guidance when the developer clarifies intent, retaining material
rationale and using Git for previous versions.

# Architectural decision records

Each record explains one coherent choice, its rationale, and consequences.
The alphabetical decision index lives in [CONTRIBUTING](../../CONTRIBUTING.md#architectural-decision-records).
The [decision-record policy](decision-records.md) defines this boundary.

Use descriptive lowercase hyphenated filenames, a short title, an Important
summary, and focused context/decision/status sections. Explain what is working
and what is an adopted contract for future implementation. Operational commands
and file inventories belong in guides that link to the relevant decision.

Review affected ADRs with architecture changes; preserve rationale, and let Git
retain prior revisions. Keep ADRs free of internal navigation links; external
sources may support a decision. OpenAPI and workflow-graph decisions from
Operations do not apply to this editor.
